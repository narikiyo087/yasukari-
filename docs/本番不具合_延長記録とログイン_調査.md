# 本番不具合の調査（2026-09-15）

対象：本番稼働中の実ヤスカリ（`yasukari-` / Next.js Pages Router + DynamoDB + Cognito）
報告された事象：
1. **延長記録がマイページに表示されない（残らない）**
2. **ログイン問題**（あわせて Google アカウント認証の導入を検討したい）

コードは読んだだけで、**まだ何も直していない**。

---

## 1. 延長記録がマイページに残らない

### 結論：記録が消えているのではなく、**そもそも「延長した」という記録が作られていない**

延長の決済が終わると、`pages/mypage/rentals/extend/checkout/[reservationId].tsx` が
次の3つをするだけで終わる。

1. Pay.JP で決済（`/api/payments/payjp`）
2. **予約レコードを上書き**（`PATCH /api/reservations/{id}`）
3. 完了メールを送る（`/api/reservations/extension/notify`）

2 で送っているのは `returnAt` / `paymentId` / `paymentDate` / `extensionPaidFlag` の4つ。
**延長そのものを表す行（何日延ばしたか・いくら払ったか・いつ延長したか）はどこにも作られない。**
3 のメール送信APIは**何も保存しない**（送るだけ）。

### その結果、マイページの表示が食い違う

`pages/mypage/index.tsx` が出しているのは次の3つ。

| 表示 | 出どころ | 延長後どうなるか |
|---|---|---|
| 利用期間 | `pickupAt` → `returnAt` | **返却日だけ伸びる**（ここは正しく変わる） |
| お支払い金額 | `paymentAmount` | **元の金額のまま。延長料金が加算されない** |
| お支払い日 | `paymentDate` | **延長の決済日に上書きされ、元の予約の決済日が消える** |

つまりお客様から見ると、**期間だけ伸びて、金額は元のまま、支払日だけ知らない日付に化ける**。
「延長した」という事実を示すものが画面に1つも無い。

### さらに悪い副作用

- **`paymentId` が延長の課金IDで上書きされる。**
  元の予約の Pay.JP 課金IDが失われるので、**元予約の返金・領収書の突き合わせができなくなる**。
- **2回目の延長は1回目を上書きする。** 履歴が無いので1回目は完全に消える。
- `extensionPaidFlag` は **true/false だけ**。日数も金額も持たない。
  しかもこのフラグを読んでいるのは**管理画面だけ**（`pages/admin/dashboard/reservations/index.tsx:236`）で、
  **マイページには延長を表示する実装が1行も無い**（`pages/mypage/rentals/[reservationId].tsx` と
  `past-reservations.tsx` に「延長」の文字が無い）。

### 別件で見つけた事故：PATCH のたびに項目が消える

`lib/reservations.ts` の `updateReservation()` は `PutCommand`（**項目まるごと置き換え**）で、
書き込む中身は `reservationToRecord()` が組み立てたものだけ。
一方 `normalizeReservation()` は、そこに**含まれていないキーも読んでいる**。

読むのに書かないキー＝**更新のたびにDynamoDBから消える**：

- `parking_number`（**駐車位置**）
- `thumbnail_url` / `store` / `pickup_datetime` / `return_datetime` / `id`（旧い別名キー）

`parking_number` は実害がある。**延長したり、管理画面で予約を1か所直したりするだけで、
その予約の駐車位置が消える。** セルフ店の受け取り案内に影響する。

### 直し方（案）

**A. 延長を「記録」として持つ**（本命）

予約の上書きだけで済ませず、延長1回につき1行を残す。

```
RentalExtension
  extensionId / reservationId / 延長前の返却日時 / 延長後の返却日時
  延長日数 / 金額 / Pay.JP課金ID / 決済日時 / 操作者（本人 or スタッフ）
```

- 予約側の `paymentId` は**元の予約のものを保持**し、延長の課金IDはこの行に持たせる。
- `paymentAmount` は「元の金額」と「延長ぶん」を分けて持ち、合計は計算で出す。
- マイページの予約詳細に「延長の履歴」を出す（何日・いくら・いつ）。
- 管理画面の `extensionPaidFlag` も、この行の有無から計算できる（フラグは要らなくなる）。

**B. `updateReservation` の項目消えを止める**（先に単独で直せる・小さい）

`reservationToRecord()` に `parking_number` を足す。
あわせて、**読むキーと書くキーがずれていないかをテストで機械的に見張る**
（ずれた瞬間に落ちるようにしないと、また別の項目で同じ事故が起きる）。

**C. 応急処置**

Aを作るまでの間だけでも、
「`paymentId` を上書きしない」「`paymentAmount` に延長ぶんを加算する」の2点は先に直せる。
**すでに延長済みの予約の失われたデータは、Pay.JP 側の課金履歴から復元するしかない。**

## 2. ログイン問題

### 結論：**1時間で必ずログアウトする作りになっている**

いまの認証は **Cognito Hosted UI** を使っている（`lib/cognitoHostedUi.ts`）。
ログインの入口は `buildAuthorizeUrl()` で、ここが

```ts
response_type: 'token'   // ← インプリシット・フロー
```

になっている。これが原因。

1. **インプリシット・フローでは Cognito はリフレッシュトークンを発行しない。**
   実際、リポジトリ全体を検索しても `refresh_token` という文字が**1か所も無い**。
2. コールバック（`pages/auth/callback.tsx`）は URL の `#` から `id_token` / `access_token` を拾い、
   `/api/auth/store-tokens` が `Max-Age = expires_in`（**既定3600秒＝1時間**）の Cookie にする。
3. **1時間経つと Cookie が消え、更新する手段が無い。**
   `/api/me` が `user: null` を返し、マイページは `/login` へ飛ばす。

→ 「ログインしたのにしばらくすると切れる」「マイページを開いたら急にログイン画面に戻る」
　　という症状なら、これで説明がつく。

**あわせて安全面の問題**：インプリシット・フローはトークンを**URLの断片に載せる**ので、
ブラウザの履歴に残る。OAuth 2.1 では非推奨、AWS も現在は推奨していない。

### 直し方：**認可コード＋PKCE に変える**

```ts
response_type: 'code'    // ＋ code_challenge / code_verifier（PKCE）
```

- **リフレッシュトークンが発行される**（Cognito の既定で30日）。
  期限が切れる前に静かに更新できるので、**使っている最中に落ちなくなる**。
- トークンがURLに出ない。
- リフレッシュトークンは **HttpOnly Cookie** に入れ、更新はサーバ側（`/api/auth/refresh`）で行う。

※ `buildSignupUrl()` はすでに `response_type: 'code'` になっている。
　 **入口によってフローが違う**状態なので、ここも揃う。

### Google アカウント認証について：**いまの作りなら小さく入る**

すでに Cognito Hosted UI を使っているので、**作り直しは要らない**。

1. Google Cloud で OAuth クライアントIDを作る
2. Cognito ユーザープールに Google を ID プロバイダとして追加し、属性を対応づける（email / name）
3. アプリクライアントの「有効な ID プロバイダ」に Google を追加
4. ログイン画面に「Google で続ける」を置く
   （`buildAuthorizeUrl()` に `identity_provider=Google` を付けるだけ）

**コードの変更は 4 だけ**で、残りは AWS と Google の設定。

**先に決めておきたいこと**

- **同じメールアドレスの既存アカウントと、Googleのアカウントをつなげるか。**
  つながないと「Googleで入ったら過去の予約が見えない」別人扱いになる。
  Cognito の**アカウントリンク**を使えば1人にまとめられるが、**後からやると面倒**なので最初に決めたい。
- 既存のパスワードログインを**残すか、置き換えるか**。

**順番の提案**：先に「認可コード＋PKCE」に直す（ログイン切れを止める）→ そのうえで Google を足す。
逆にすると、Google で入った人も1時間で切れる。

---

## 手を付ける順（提案）

| 順 | 中身 | 効き目 | 大きさ |
|---|---|---|---|
| 1 | ログインを認可コード＋PKCEに変える | **1時間で切れるのが止まる** | 中 |
| 2 | `updateReservation` の項目消えを止める（駐車位置） | 静かに消えていたデータが残る | 小 |
| 3 | 延長を「記録」として持つ＋マイページに出す | 報告された事象の本丸 | 中〜大 |
| 4 | Google ログインを足す | 利便性 | 小（設定が主） |

2 は独立して先に出せる。3 は 2 と同じファイルを触るので続けてやるのがよい。
